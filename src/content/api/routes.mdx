RsOpsHub exposes REST API routes under `/api/`, colocated server actions for mutations, and UI routes organized into three Next.js route groups: `(marketing)` for the public site, `(auth)` for login flows, and `(app)` for workspace pages.

## API endpoints

Every mutating endpoint calls `requireSameOrigin(req)` to reject cross-origin requests before any role check. See [Authentication](/api/authentication) for how session cookies and guards work.

| Endpoint | Methods | Auth | Purpose |
|---|---|---|---|
| `/api/auth/login` | POST | Public | Owner login. Rate-limited (8/min per IP) with exponential lockout. |
| `/api/auth/logout` | POST | Any session | Destroy the `rs_session` cookie. |
| `/api/auth/viewer` | POST | Public | Viewer login with email and 16-character access code. Same rate-limit and lockout as owner login. |
| `/api/auth/viewer/lookup` | POST | Public | List workspaces a returning viewer email can re-enter. |
| `/api/auth/viewer/select` | POST, PUT | Public | Re-issue a session for a workspace the viewer already holds a join for. |
| `/api/copilotkit` | POST | Session (owner or viewer) | CopilotKit AI assistant runtime. Rate-limited at 40 requests/min per IP. Same-origin guard. |
| `/api/cron` | GET, POST | Bearer `CRON_SECRET` | Trigger nightly background jobs. `maxDuration` is 300 s, budget 260 s. Accepts `jobs` and `workspaceId` query parameters. |
| `/api/integrations/google/start` | POST | Owner | Begin the Google OAuth consent flow. |
| `/api/integrations/google/callback` | GET | Public (state + nonce cookie) | Google OAuth redirect target. Validates HMAC-signed state and HttpOnly nonce. |
| `/api/integrations/google/disconnect` | POST | Owner | Revoke and clear the workspace Google connection. |
| `/api/integrations/notion/image` | GET | Session | Proxy for Notion-hosted images (avoids CORS/referrer issues). |
| `/api/linear/proxy` | GET | Owner | Proxy Linear-hosted file URLs through the workspace Linear API key. Restricted to Linear hostnames. |
| `/api/owner/avatar` | GET | Public | Serve the owner avatar image. |
| `/api/owner/avatar/upload` | POST | Owner | Upload a new owner avatar. |
| `/api/spreadsheets/[id]` | GET | Session | Download a locally stored spreadsheet blob. Respects share gating for viewers. |
| `/api/uploads` | POST | Owner | General image upload (MIME + magic-byte validation, random filename). Max 25 MB. |
| `/api/workspaces/[slug]/logo` | GET | Public | Serve a workspace logo. |
| `/api/workspaces/[slug]/logo/upload` | POST | Owner | Upload a workspace logo. |

## Proxy middleware

The proxy function in `src/proxy.ts` runs on every request that matches `/((?!_next/static|_next/image|favicon.ico).*)` and does two things.

### Security headers

Every response receives these headers:

| Header | Value |
|---|---|
| `Content-Security-Policy` | Restrictive policy. `default-src 'self'`, allows inline styles, Google Fonts, Notion/Google Docs iframes, Google OAuth form action, Vercel analytics. `frame-ancestors 'none'`. Development mode adds `'unsafe-eval'`. |
| `X-Frame-Options` | `DENY` |
| `X-Content-Type-Options` | `nosniff` |
| `Referrer-Policy` | `strict-origin-when-cross-origin` |
| `Permissions-Policy` | `camera=(), microphone=(), geolocation=(), interest-cohort=()` |
| `Cross-Origin-Opener-Policy` | `same-origin` |
| `Cross-Origin-Resource-Policy` | `same-origin` |
| `Strict-Transport-Security` | `max-age=63072000; includeSubDomains; preload` (production only) |

### Session pre-check

For non-public paths, the proxy checks whether the `rs_session` cookie is present and has a valid shape (a `v2:` prefix or a legacy `body.mac` format). If missing or malformed, it redirects to `/sign-in?next=<original-path>`. This is an inexpensive shape check only. Full decryption and signature validation happen in the route handler's `getSession()` call.

Public paths bypass this check. These include `/`, `/sign-in`, `/access`, `/docs`, `/docs/*`, `/solutions/*`, `/llms.txt`, `/api/auth/*`, `/api/workspaces/*/logo`, `/api/owner/avatar`, `/api/integrations/google/callback`, `/api/health`, static assets, and Next.js internal routes.

## Server actions

Most mutations use Next.js server actions rather than REST endpoints. Actions are defined in `actions.ts` files colocated with the pages that call them, marked with `"use server"`, and called directly from client components. They share Next.js built-in CSRF protection (action ID and `Next-Action` header).

### Guard pattern

Every action calls its authorization guard as the first statement:

- **Write actions** call `requireOwner()`. All task creation, content updates, integration configuration, workspace settings, document editing, and similar mutations require owner authorization.
- **Read-only actions** call `requireWorkspaceAccess(wsId)`. Viewers can use these to fetch data scoped to a workspace they hold a valid join for.

After the guard, the action validates input with Zod, performs the database operation, calls `revalidatePath` for any affected cache, and returns `{ ok, error? }`.
