## What RsOpsHub is

RsOpsHub is a self-hosted workspace that pulls the tools an indie operator, technical founder, or small team relies on into one place. It mirrors content from Reddit, Hacker News, and dev.to, project work from Linear, documents from Notion and Google Docs, spreadsheets from Google Sheets, calendar events from Google Calendar (with in-app Google Meet creation), and site analytics from PostHog and Cloudflare. A built-in AI assistant powered by CopilotKit can create tasks, sync data, schedule meetings, and generate reports on your behalf.

There is no public signup and no hosted version. You deploy RsOpsHub to your own infrastructure, connect it to your own PostgreSQL database, and own all of your data.

RsOpsHub is proprietary and not published as a public package or open-source repository.

## Single-owner model

Every deployment has exactly one owner, defined by the `OWNER_EMAIL` and `OWNER_PASSWORD` environment variables. The owner has full read and write access to every workspace. Viewers join a workspace using a 16-character access code and get read-only access. There is no multi-user editing, no SSO, and no per-seat pricing.

This model fits several shapes well:

- A solo operator who wants every signal in one screen.
- A founder who owns ops while the team follows along read-only.
- An agency lead who shares progress with each client in a separate workspace.
- A small team that wants a single dashboard instead of five SaaS subscriptions.

## Workspaces

The workspace is the core organizational unit. Each workspace has its own integration credentials, access code, data, and viewer roster. Nothing is shared across workspaces, so a "Client A" workspace, a "Personal" workspace, and a "Side project" workspace never overlap.

## Integrations

All integrations are per-workspace unless the credential can only live in an environment variable.

| Provider | Auth type | What it does |
|---|---|---|
| Hacker News | Public handle | Mirrors posts and comments with metrics |
| Reddit | Public handle | Mirrors posts and comments via public feeds |
| dev.to | Public handle + optional API key | Pulls published articles and reactions by username. An optional per-workspace API key unlocks drafts and page-view counts. |
| Linear | Per-workspace API key | Syncs issues, comments, notifications, and templates. Supports creating and editing issues from the app. |
| Notion | Global token (env var) | Document mirroring and page editing, scoped per workspace by a parent page ID |
| Google Docs, Sheets, Calendar, Meet | Per-workspace OAuth | Document and sheet sync, shared-with-me inbox, calendar events, and in-app Meet creation |
| PostHog | Per-workspace API key | Referral traffic and detailed analytics breakdown (pages, sources, countries, devices, custom events) |
| Cloudflare | Per-workspace API token | Zone-level edge analytics (requests, cache, bandwidth, threats, protocol mix) |
| OpenAI or LiteLLM | Global key (env var) | AI-generated work-log summaries and the CopilotKit assistant. Falls back to deterministic text when no key is set. |

## Where RsOpsHub fits

RsOpsHub sits at the intersection of four categories that each cover part of the workflow:

- **Generic workspaces** (Notion, ClickUp) handle docs and tasks well but do not track content distribution or site traffic out of the box.
- **Daily planners** (Sunsama, Akiflow) combine tasks and calendars into a timeline but know nothing about posts, metrics, or analytics.
- **Social schedulers** (Buffer, Typefully) write and publish posts but stop at their own networks and never meet your task list or work log.
- **Web analytics** (PostHog, Plausible, Cloudflare dashboard) show who visited which URL but have no context about what you shipped or which post drove the traffic.

RsOpsHub does not replace these tools. Linear, Notion, Google, PostHog, and Cloudflare stay the systems of record. RsOpsHub reads them together in one screen and writes back where it makes sense (creating a Linear issue, scheduling a Meet call, archiving a document). It deliberately does not auto-publish posts to social networks and does not provide product experimentation features such as funnels, session replay, or A/B tests.

## Tech stack

| Layer | Technology |
|---|---|
| Framework | Next.js 16, React 19 |
| Database | PostgreSQL 14 or newer, managed through Prisma 5 |
| Styling | Tailwind CSS 4 |
| AI | CopilotKit 1.77 with OpenAI or LiteLLM |
| Runtime | Node.js 20 or newer. Bun is used for dependency installation and scripts. |
