---
title: Environment variables
description: Every environment variable RsOpsHub reads, its validation rule, its runtime effect, and what happens when you rotate it.
---

RsOpsHub validates environment variables at startup with Zod (`src/env.ts`). In production the process exits immediately if any required variable is missing or invalid. In development, placeholder values are substituted and a warning is printed.

## Required variables

These six variables must be set for a production deployment. All are validated before the app accepts requests.

| Variable | Validation | Effect |
|---|---|---|
| `DATABASE_URL` | `z.string().url()` | Prisma connection string for PostgreSQL. |
| `OWNER_EMAIL` | `z.string().email()` | The single owner account's email address. Compared (lowercased, constant-time) during login and stored on the `OwnerProfile` row. |
| `OWNER_PASSWORD` | `z.string().min(12)` | Verified with scrypt at login. A SHA-256 fingerprint is embedded in the owner session cookie, so **rotating this value invalidates all active owner sessions**. |
| `SESSION_SECRET` | `z.string().min(32)` | HMAC-SHA256 key used to sign session cookies. **Rotating invalidates every session** (owner and viewer). |
| `TOKEN_ENC_KEY` | `z.string().min(32)` | AES-256-GCM key for encrypting third-party tokens at rest (Google refresh tokens, Linear API keys, dev.to API keys, PostHog API keys, Cloudflare API tokens). A 32-byte base64url-encoded value is preferred, but any string of at least 32 characters is accepted. **Rotating invalidates all stored encrypted tokens.** |
| `APP_URL` | `z.string().url()` | Base URL used for OAuth redirect URIs, notification deep links, and cookie `Secure` flag derivation. Defaults to `http://localhost:3000` when unset. |

### Generating secrets

Use `openssl` to create cryptographically random values for `SESSION_SECRET` and `TOKEN_ENC_KEY`:

```bash
# 48-byte random string, base64url-encoded (meets the 32-char minimum)
openssl rand -base64 48
```

## Optional variables

Omitting these variables disables the corresponding feature. The app still starts.

### AI and LLM

| Variable | Validation | Effect |
|---|---|---|
| `OPENAI_API_KEY` | `z.string().optional()` | Enables the CopilotKit assistant (model `gpt-4o-mini`) and AI-generated work-log summaries via the OpenAI chat completions API. Without it, CopilotKit loads an empty adapter and summaries fall back to deterministic text. |
| `LITELLM_API_KEY` | `z.string().optional()` | Fallback LLM provider, used only when `OPENAI_API_KEY` is absent. Routed through `LITELLM_BASE_URL` with model `evals-openai/gpt-4o` for CopilotKit and `evals-openai/gpt-4o-mini` for work-log summaries. |
| `LITELLM_BASE_URL` | `z.string().url().optional()` | Base URL for the LiteLLM-compatible endpoint. Only meaningful when `LITELLM_API_KEY` is set. |

### Integrations

| Variable | Validation | Effect |
|---|---|---|
| `NOTION_TOKEN` | `z.string().optional()` | Global Notion internal-integration token, shared across all workspaces. Enables page search, CRUD, block editing, and comments through the Notion API. |
| `GOOGLE_OAUTH_CLIENT_ID` | `z.string().optional()` | Google OAuth web-app client ID. Both this and `GOOGLE_OAUTH_CLIENT_SECRET` are required for the Google integration (Docs, Sheets, Calendar, Meet). |
| `GOOGLE_OAUTH_CLIENT_SECRET` | `z.string().optional()` | Paired with the client ID for the OAuth authorization-code exchange. |

### Infrastructure

| Variable | Validation | Effect |
|---|---|---|
| `CRON_SECRET` | `z.string().optional()` | Bearer token required by the `/api/cron` endpoint. Without it, cron requests are rejected. On Vercel, set this as an environment variable; the platform automatically sends it as a bearer token when triggering configured cron jobs. |
| `NODE_ENV` | `z.enum(["development", "production", "test"]).default("development")` | Controls Prisma log level, cookie `Secure` flag, and whether env validation hard-fails. |

## Prisma-only variable

`DIRECT_DATABASE_URL` is **not** part of the `src/env.ts` schema and is not validated at startup. It appears only in `prisma/schema.prisma` as the `directUrl` for migrations and `prisma db push`. Point it at a non-pooled PostgreSQL endpoint when your primary `DATABASE_URL` uses a connection pooler such as PgBouncer.

## Per-workspace credentials

Several integration credentials are configured per workspace through the Settings UI, not as environment variables. They are stored AES-256-GCM encrypted (using `TOKEN_ENC_KEY`) on the `Workspace` row:

- **Linear** API key
- **dev.to** API key
- **PostHog** API key, project ID, and host
- **Cloudflare** API token and zone ID
- **Google** OAuth refresh token (written automatically after the OAuth flow)

## Rotation reference

| Secret | What breaks on rotation |
|---|---|
| `OWNER_PASSWORD` | All active owner sessions. Viewers are unaffected. |
| `SESSION_SECRET` | Every active session (owner and viewer). |
| `TOKEN_ENC_KEY` | All encrypted per-workspace tokens (Google, Linear, dev.to, PostHog, Cloudflare). Re-enter each credential in the workspace settings after rotating. |

## Development defaults

When `NODE_ENV` is not `production` (and the process is not a production build phase), missing required variables are replaced with hardcoded placeholders so the app can start for local development:

| Variable | Dev placeholder |
|---|---|
| `DATABASE_URL` | `postgresql://postgres:postgres@localhost:5432/rsopshub?schema=public` |
| `OWNER_EMAIL` | `owner@localhost` |
| `OWNER_PASSWORD` | `dev-only-passphrase-change-me` |
| `SESSION_SECRET` | `dev-session-secret-replace-in-production-only-32` (48 characters) |
| `TOKEN_ENC_KEY` | `dev-token-enc-key-replace-in-production-only-32!!` (49 characters) |
| `APP_URL` | `http://localhost:3000` |

These placeholders are not secure. Never rely on them outside local development.
